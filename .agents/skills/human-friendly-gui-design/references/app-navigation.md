# アプリ全体の導線を選ぶ

アプリの主な使い方に応じて、ホーム形式かサイドパネル形式を選ぶ。モード数ではなく、作業の独立性と往復する頻度から決める。今回の原本では両者の併用を採用せず、同じモード選択を重ねない。

| 判断材料 | ホーム形式 | サイドパネル形式 |
|---|---|---|
| モードの関係 | 独立した目的の道具を、開始時に一つ選ぶ | 同じ対象を扱う関連作業を、途中で切り替える |
| 移動頻度 | 選んだモード内で作業や設定が完結する | 検索・編集・確認などを頻繁に往復する |
| 説明の必要性 | 名前だけでは何を始めるか判断しにくい | 短いラベルから行き先が分かる |
| 作業領域 | 選択後は画像・編集などへ面積を使いたい | 移動手段へ面積を割く価値がある |
| 開始と再開 | 途中の作業へ直接入る経路を用意する | 前回の作業や主作業を開き、ナビから移動する |

利用者の想定では、`foam-cell-analysis`のように各モードが独立して完結し往復が少ないアプリはホーム形式、`chemical_reaction_library`のように関連モードを行き来するアプリはサイドパネル形式が合う。アプリ名を一般的な判定条件にせず、実際の作業の流れを優先する。

## 原本

- [ホームで作業を選ぶ](../assets/templates/app-navigation/home.html)：各パネル全体を一つのリンクにする。名前と目的を読んで選べ、キーボードでも一回のフォーカスで操作できる。リンク内に別のボタンを入れない。作業中にはホームへの戻り口を置く。
- [サイドパネルで切り替える](../assets/templates/app-navigation/sidebar.html)：関連モードへ直接移動し、現在地と共通対象を示す。広い画面ではナビを表示し、狭い画面では表示・非表示を切り替える。狭い画面で移動先を選んだ後はナビを閉じ、作業領域を確保する。

主作業が一つで開始先が明確なら、専用ホームは不要。ナビゲーションもサイドパネルに限定せず、画面幅・移動頻度・階層に応じて上部配置や折り畳みを検討する。画像・表の作業領域と競合する場合は、常時表示の費用を評価する。

## モードをつなぐときの確認

対象データ、プロジェクト、選択条件、入力、作業位置、未保存状態のうち、継続に必要なものを引き継ぐ。モードを移ると適用対象が変わる場合は区別を示す。頻繁な可逆の切替へ不要な確認を挟まない。

ブラウザでは直接URLと履歴移動、デスクトップではウィンドウ間の対象や状態の扱いを必要な範囲で確認する。原本はURLハッシュによる移動とページ内メモ保持を再現するが、本番のルーティングや永続的な復元を保証しない。

各モードには必要な作業別テンプレートを組み合わせる。ホームを設ける場合も、再開先や直接URLから作業へ入れるようにし、常にホームを経由させない。

ホームには目的選択と必要な再開情報を置き、用途のない指標・グラフ・機能説明を追加しない。ホームの原本は状況把握ダッシュボードではない。
